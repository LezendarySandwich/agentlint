# 11 — UI

A local web interface for seeing and eventually editing your configuration.

**This is core, not optional.** The reasoning is in the design doc; the short version is that the
product's payoff is deletion, and deletion only happens when it's visible and reversible. A
terminal table of 412 skills delivers neither.

## The UI as the primary interface (decided with the user 2026-10-04)

Every feature reaches the UI, new ones first; the CLI stays for developers who prefer it, and only commands the
changes made meaningless go (`config path`, `usage --forget`, the hidden `--history` alias). The offline HTML report
(`report --html`) is dropped: the live UI shows everything, and a file holding the configuration's full text invites
sharing. What the UI gains — each built with its own checklist item:

- **Settings** (settings live in the database; built 2026-10-04, "Views › 7. Settings"): every setting with its
  default; the daily-sync switch (launchd or cron, its time, the last sync's result); archive totals; the version;
  **Privacy › Forget everything**, confirmed by a dialog listing what goes and typing `forget` (the server requires
  the string; refused while a job runs).
- **Dismiss / Show again** on a finding, with a required reason (replacing the copied `suppress` command), and a
  **Dismissed** screen: every suppression across projects with its date, reason and state (built 2026-10-04,
  "Views › 3. Findings" and "Views › 8. Dismissed").
- **Configuration › What changed**: a project's snapshots and the diff from the previous one (built 2026-10-04;
  "As built" below).
- **Tests**: the **Plan** (what `rank` prints), **Jobs** (start — the one-time onboarding first — progress, stop,
  resume, salvage) and **Situations** (generate, then keep, drop or edit each, with its "what matters"), and **Tests ›
  Results**, every test and its results as a table; the test settings and the removed-tools override in Settings ›
  Tests (built 2026-10-05, Results 2026-10-06; "Tests" below).
- **Diagnostics**: agentlint's findings about itself, never in the Findings list or its counts (built 2026-10-04;
  "As built" below).
- A one-time **first-run** panel: what is read, what is kept, how long (built 2026-10-04, "Views › 7. Settings").

**Writes** are POST endpoints. Every one takes the token from a header only, checks Host and Origin, accepts a JSON
body only (there is no CORS handler, so a cross-origin JSON POST fails its preflight), caps the body's size and
checks every value on the server. There is no `--allow-edit` flag: every write is allowed whenever the UI runs.

**Test jobs from the UI.** Start freezes the plan and launches a worker process of its own (its own process group,
its log under the store), which survives the server: closing the terminal doesn't stop a job, and the next
`agentlint ui` shows it. The page polls for progress. Stop sends Ctrl-C to the worker's process group — the running
harness and its hooks stop too, and the engine reports the interrupted run — escalating to a kill after a grace
period; Resume continues the frozen plan. While a job runs on macOS, agentlint keeps the Mac from idle-sleeping
(`caffeinate -i`, released when the job ends or stops; closing the lid still sleeps) and says so on the job's page
and at onboarding. Start is disabled, with the reason, when the server itself runs inside an agent session (the
adapter decides from the environment): the harness can't be started from there.

## Why a local web server

| Option | Verdict |
|---|---|
| Terminal output only | Fine for findings, useless for exploring 412 entities or reading source text in context |
| Rich TUI | No server, fast, but poor at wide tables, diffs, and text editing; and it's a lot of work for a worse result |
| **Local web server** | **Chosen.** Handles the data volume, good at diffs and drill-down, supports editing later, no deployment |
| Static HTML report | Shipped first (v0, 2026-10-02), dropped 2026-10-04: read-only, stale, and a file holding the configuration's full text invites sharing |
| Editor extension | Harness-coupled, large surface, wrong dependency direction |

```
agentlint ui          # starts localhost, opens browser
```

## Not a plugin, still

Non-negotiable #4 in `AGENTS.md` stands: nothing installs itself into the configuration being
measured. A local web UI contributes zero tokens to any agent context, so it doesn't conflict.

The in-session "why did you just do that?" skill stays out of scope. The **Context view** below
serves that need from outside the session, which is better anyway — it can show what was loaded
without competing for the attention it's measuring.

## Design principles

From the user, 2026-10-02, after the first report: it rendered, but "doesn't have structure". Every view follows
these:

- **Colour and icons, not words.** Severity, authority, when a source loads, lifecycle state, confidence and
  testability are each a colour or an icon with a tooltip. Words only where nothing else can say it.
- **A flow.** Start at an overview that says what matters most and what to do next; every number leads to the
  list behind it; detail opens beside the list, never in place of it, so you never lose your place.
- **Obvious hints.** Every icon has a tooltip; empty states say what to do; filters show what they hide.
- **Simplicity.** Dense, aligned lists with plenty of whitespace; keyboard-first (`j`/`k` to move, `Enter` to open,
  `Esc` to close, `/` to search); no chrome that doesn't earn its place; opinionated defaults instead of settings.

The 2026-10-02 wording also asked for "Linear-like simplicity" and "a quiet neutral palette with one accent". The
visual language that carries these out is now the **Quiet ledger** (`docs/02-design.md` decision log,
2026-10-03; the checklist's "UI redesign" section), which replaced the indigo accent:

- **Colour.** Warm greys: page `#f9f9f7`, panel `#fcfcfb`, sidebar `#f3f3f0` (dark: `#0d0d0d`, `#1a1a19`,
  `#121211`). Text is ink, secondary or muted (`--ink`, `--sec`, `--mut`), each at least 4.5:1 on every surface in
  both modes. There is no colour accent: ink marks what is current — the cursor row is `--cur` with a 2 px ink bar
  at its left, the open row the same at weight 500, focus a 2 px ink ring, a pressed toggle an ink border. Links
  are ink, underlined on hover. Hue is used for two things only: **severity** (error `--err`, warning `--warn`;
  info is neutral, `--mut`) and **who put the text there**. Severity hues are for glyphs, never small text
  (`#ab6400` warning is 4.49:1 on the panel). Who put the text there is one blue ramp in three steps, one per
  group (below): `--b1`/`--b2`/`--b3` are `#184f95`, `#2a78d6`, `#86b6ef` in light (darker = more yours) and
  `#86b6ef`, `#3987e5`, `#184f95` in dark; lightness steps one way in each mode, at least 0.06 apart, and the faint
  end is 2.06:1 on the light panel and 2.15:1 on the dark one (tokens.test.ts). The six authority colours
  (`--auth-*`) are gone. Formatted JSON is
  neutral (keys secondary, strings ink, numbers secondary, null muted). The tooltip is ink on light; in dark it is
  `#262624` with a 1 px `#3a3a37` edge, since it is barely darker than the panel.
- **Type.** The system font (`system-ui`), one monospace stack (`--mono`). Four sizes: 12 (meta, labels, code), 13
  (body), 15 (titles), 20 (the few figures); the wordmark on the home is 30 px, a logo, and the only exception. Weights 400, 500 and 600. No caps and no letter-spaced labels.
  Digits are tabular only in columns (`.num`, group counts).
- **Space and shape.** A 4 px scale (4, 8, 12, 16, 24, 32, 48; 2 px only for hairlines and bar gaps); rows and
  group heads are 32 px. Radii: 2 for bar segments, 4 for controls (keys, buttons, inputs, chips, code), 6 for
  panels, 50% for dots. No chips, no tinted boxes and no helper text in a detail pane: its facts are one property
  list (`dl.props`, 76 px labels, 12 px — the finding's, the source's, the listing's, untraced text's and the
  entity's), what a text is is a plain paragraph; what to do comes after an arrow; the session reader sets your prompts apart by
  weight (15 px, 500), a hairline and the time, not a coloured left border on a tinted box, tints nothing else
  (code blocks are text, not boxes) and links what a call used as plain text; a pointed line or a search match is `--cur` with an ink mark.
- **Motion.** Only the chevrons turn, and the 2 px line runs while a reading is under way; `prefers-reduced-motion`
  turns every transition and animation off, and every animation has a still form there (the line becomes a faint
  full-width bar).
- **Glyphs: one per meaning.** About 20 marks — the three severities, disclose, close (or clear a filter), search,
  copy, nothing found, the five load times, the three confidences, can't be tested, seen, not seen, untraced,
  suppressed, dismissed-but-changed, what this is, archived, started here (the home's pin) — beside one icon per view (in the sidebar only) and
  one per entity role (skill, agent, tool, command, path, domain, anything else; a session's tool calls and
  subagents use the tool and agent marks, meaning the same thing). No glyph means two things: the info severity
  and "what this is" differ, the not-in-context load is a slashed circle and not the eye that means "not seen",
  copy no longer doubles as a duplicate-name icon (check-kind icons are gone), and a failed tool call is the error
  glyph. The severities are drawn in SVG, not taken from Lucide: a filled octagon (`--err`), a filled triangle
  (`--warn`), an outlined circled i (`--mut`). Lucide icons are 14 px in rows and 16 px in heads and for close,
  at one 1.5 px stroke (`absoluteStrokeWidth`). No heading carries an icon (no card, strip, `h2` or `h3` icons),
  decorative icons beside words are gone (the reader's voices, thinking, injected, compaction, recap, "more"; the
  sidebar's footer), and the stock AI sparkle is retired (a skill is a book). Every glyph is listed once in the
  `?` legend with its meaning — every view's icon too, beside its key, and What changed's, which has no key, with
  none (Help lists `PAGES`, not just the keyed `VIEWS`). All are named in one place, `ui/src/ui.tsx` (`MARK`, `NAV_ICON`, `ROLE_ICON`),
  the only module that imports Lucide; `ui/src/glyphs.test.ts` pins that, that no glyph serves two meanings, and
  the counts, and `App.test.tsx` that no two legend rows share a glyph, every `NAV_ICON` has its row, and no
  heading has one.

Each vocabulary and derived value is written once: the visibility type in `contract.ts` (`Visibility`) and its
words in `format.ts` (`VISIBILITY_WORDS` for tooltips and the legend, `VISIBILITY_SHORT` beside a mark, "not known"
for unknown); a content's tokens through `model.ts`'s `tokensOf` and whether a source can be tested through
`isTestable`; what Configuration opens through `Target`/`targetKey`/`configHref`. (format.ts's unused `tokens()`,
`alwaysOn()`, `ablatable()` and `tail()` were deleted, 2026-10-04, design review 12.2–12.3.)

A count beside its noun goes through `format.ts`'s `counted(n, one, many)`, which writes the singular the caller
gives for 1 ("1 prompt", "1 source", "1 token") and never guesses an English plural; review round 12 moved the
session rows and reader, the Configuration groups, token tooltips, a listing's parts, "N more characters", the
sidebar's sessions read and "of your N turns" onto it, which had printed "1 prompts" and "1 sources". Round 13
moved the rest: where observed text was seen (`seenIn`, "in 1 of the 1 recent session read", in the Seen mark's
tooltip that Help shows and in a source's and untraced text's detail), the overview's "the other 1 was never
used", Skills and agents' strip ("of 1 skill or agent used since <date> · across your 1 turn"), and the
hand-written ternaries for findings, more locations, more checks, checks not evaluated, sessions, subagents and a
figure's unit. A count drawn apart from its noun (`<strong>3</strong> sessions`) takes the noun from
`noun(n, one, many)`, which also never guesses.

Every value is a token in `ui/src/styles.css`, and `ui/src/tokens.test.ts` reads that file to pin the contrast
pairs above in both modes and the scales: every font size, weight, radius and spacing, no colour outside the
token blocks, no caps, no `Inter`, no indigo, tabular digits only in columns, and the reduced-motion block.

### The safe primitive is disable, not delete

```
[ Disable ]  → moves to quarantine, reversible, one click back
[ Delete  ]  → not offered
```

Quarantine lives at `~/.agentlint/quarantine/<timestamp>/` with a manifest recording the original
path, content hash, and why it was disabled. Restore reverses the manifest.

People don't remove things because removal feels irreversible. Make it reversible and they will.

### Package-managed files are not edited in place

A plugin update will clobber any edit. Rules:

| Target | Mechanism |
|---|---|
| User-owned file (`~/.claude/CLAUDE.md`, user settings) | Edit in place, after writing a backup and showing a diff |
| Package-managed (plugin, skill, agent definition) | **Never touch the file.** Disable via the harness's own mechanism if one exists, else record an adapter-applied override |
| Managed / policy | Not editable. Show why. |

Whether Claude Code supports disabling an individual plugin or skill via settings is
**UNVERIFIED** — check before building the editing layer. If it doesn't, the override has to be
adapter-applied, which means the UI can only disable things for *agentlint's own variants*, not for
the user's real sessions. That would substantially reduce the value of editing, so find out early.

### Every edit shows a diff and re-checks immediately

After any change, re-run static checks and show the delta:

```
✓ Disabled CLAUDE.md § "Memory"
  Always-on budget: 44,290 → 42,450  (−1,840 tokens, ≈ −$0.01 per request)
  [ Undo ]
```

That immediate, visible, reversible feedback is the entire behavior change the product is trying
to cause. Build it carefully.

## Technical shape

**A real frontend project, delivered as one self-contained HTML file** (decided 2026-10-02). The UI will grow
to six views — config, context, findings, coverage, entities, editing — with filtering over hundreds of sources,
diffs and drill-down; hand-written inline JavaScript doesn't stay maintainable at that size. So:

- `ui/` at the repository root is a TypeScript + React project (Vite): components, types that mirror
  agentlint's JSON contract, unit tests (Vitest).
- `npm run build` bundles it into **one HTML file with every script and style inlined** and no external
  references, written to `src/agentlint/ui/shell.html` and shipped inside the Python package. Users install
  and run agentlint with no frontend toolchain; only changing the UI needs Node.
- The built shell records a hash of the UI sources, and a Python test fails if the sources changed without a
  rebuild, so the shipped shell can't drift from its code.
- `ui/src/contract.ts` is held to what Python writes by a golden fixture: `tests/report/test_golden.py` builds a
  report through `report_data` from a test adapter's reading with every content state, every always-on outcome
  and findings of each lifecycle (`tests/contract_data.py`), and compares it with `ui/src/fixtures/report.ts`.
  That file is the same JSON as a TypeScript literal with `satisfies Report` — a `.json` import would widen every
  union tag to `string` and check nothing — so `npm run build` fails on a field Python writes that the contract
  doesn't describe, or one the contract requires that Python doesn't write; `ui/src/golden.test.tsx` renders every
  view, source and finding from it. `AGENTLINT_WRITE_GOLDEN=1 uv run pytest tests/report/test_golden.py` rewrites
  it after a deliberate change. The hand-written fixture in `App.test.tsx` stays, for what the views say.

VERIFIED 2026-10-02 on the reference machine: Node 23 and the public npm registry are available; a minimal
React + TypeScript app built with `vite-plugin-singlefile` came out as one 220 KB file (69 KB gzipped) with no
external references, in 69 ms.

Changing the UI needs Node 22.9+ and **npm 11+** (`engines` in `ui/package.json`): npm 10's resolver crashes on
these dependencies ("reading 'edgesOut'"). `ui/package.json`'s `allowScripts` records that `fsevents` (the dev
server's file watcher, shipped prebuilt) needs no install script. `npm run build` type-checks, bundles and
installs the shell; `npm test` runs the component tests (Vitest, jsdom).

**UI-0, built 2026-10-02, dropped 2026-10-04.** The first UI was `agentlint report --html <path>`: the shell with one
reading baked in, every source's text gzipped inside it, for offline reading. The live UI shows everything it did,
and a file holding the configuration's full text invites sharing, outside v1's one-person scope (decision log), so
the command, the shell's slots for an embedded report and the page's mode that read them are gone. The shell carries
no report: `agentlint ui` serves it, and the page fetches the report, its texts and the rest from the server.


One report document, built by one function (`cli._report`) — not one endpoint
per view: configuration, findings with their lifecycle, the last session's context and usage counts are blocks of
it (decided 2026-10-03; the sketch had `/api/config`, `/api/context`, `/api/findings`).

**The server reads sessions through a catalog** (2026-10-04, design review 10.1). `ui/catalog.py`'s
`SessionCatalog(adapter, connect)` is one harness's sessions: `listings()` (the harness's, then those only the archive
holds), `projects(here)`, `conversation(id)`, `subagents(id, ref)` and `subagent(id, agent)`, with its two bounded
caches (below, "What an open UI keeps in memory"). `Catalogs` holds one per listed harness and resolves a request's
`?harness=&project=` — only a harness and a project it lists, else `ScopeError` (400); `/api/sessions` checks the
project against the same listing it filters, so a request scans the harness and the store once. `UIServer(build,
shell, catalog=...)` takes it whole (a `Catalog` protocol in `ui/server.py`; `NoSessions` for a server of reports
only), and `cmd_ui` is left with the one `build` closure, which re-reads your settings and calls `_report`. Before,
`cmd_ui` held ten nested closures sharing those caches, which nothing outside a running `ui` could reach.

**What agentlint stored is served from its database** (2026-10-04). `ui/records.py`'s `StoredRecords(scope,
connect)` answers `/api/snapshots`, `/api/diff` and `/api/diagnostics` (the server's `Records` protocol; a server
built without one answers 404). The scope is checked by `Catalogs.scope`, as a reading's is (with no harness agentlint can read — a
harnesses setting naming none, which Settings says — all three answer 500 with the report's reason), and only
snapshots read through that harness are listed or compared. `from` and `to` are fingerprints of that project's snapshots, any unique prefix
(`sha256:` optional); none named, none matching or several matching is 400 with why, and one stored in a format this
agentlint can't read back is 500 "… can't be compared". Neither starts a reading or takes the reading lock. Reading
a snapshot back takes about 0.1 s (0.08 s for this machine's 909-source reading, VERIFIED 2026-10-04 on a copy of the
store), so each list line is kept by project, fingerprint and time, at most 256 (`KEPT_SUMMARIES`).

**What goes wrong is said, and a bug is traced** (2026-10-04, design review 10.2). A request whose scope isn't listed
is answered 400; one whose database, transcript or reading can't be read (`Unreadable`, raised by the catalog and by
`build`) 500 with why. Anything else is a bug: its `traceback.format_exc()` goes to the terminal running `agentlint
ui`, then 500 with the exception's type and message, and the server carries on. The traceback holds code and
exception messages, never the token — the request line, which can, is still never logged (`log_message`). Before,
every exception became a one-line 500 and its traceback was lost.

**UI-1, built 2026-10-03.** `agentlint ui [--cwd] [--port N] [--no-open] [--sessions N]` prints its address, opens the browser,
and serves until Ctrl-C; each page load reads the configuration again — and your settings, so Settings and `agentlint
config set` reach an open UI (a flag given at start still wins: `Options.reread`) — and `r` ("Read again") re-reads without
reloading, the report shown staying, dimmed, until the new one lands ("Loading", above). It opens on the home

(`09-adapters.md`, "Each reading is self-contained"). A page load imports what is new but never prunes: the UI prunes past `keep_days` once, as it starts

**What an open UI keeps in memory** (corrected 2026-10-04). The kept texts are what a server's readings leave
behind, and they are bounded at four scopes. Each scope's texts are about 7.7 M characters: 8.1 MB as JSON but
17.4 MB as the Python strings the server keeps. 521 of the 670 texts hold a character outside Latin-1, so CPython
stores them at 2–4 bytes a character. Four kept scopes come to about 70 MB. Everything else a reading builds is
let go when it finishes, and the adapter keeps no discovery between readings (09-adapters, "Each reading is
self-contained"). Resident memory still rises above the traced figure: the allocator keeps the high-water mark of a
reading's transient peak, about 130 MB on top of the kept texts. (This replaces a figure of "some 31 MB" for the

estimated token count by its 16-byte digest, at most 8,192 (`config/tokens.py`). VERIFIED 2026-10-04

## Security

- Bind `127.0.0.1` only. Never `0.0.0.0`.
- Random port, random token in the opened URL, required on every request (the page sends it as a header). Prevents
  other local processes and stray browser tabs from reading your config. The request log is never printed: the
  request line carries the token.
- A request must name this server as its host (`127.0.0.1:<port>` or `localhost:<port>`), so a web page can't
  reach it under its own name by DNS rebinding.
- The page gets a content security policy (no frames, nothing fetched but this server), `no-store`, `nosniff`,
  `no-referrer`.
- No external asset loads of any kind — leaks nothing.
- **It answers only its fixed endpoints**, never a file by path: the report and its texts, what agentlint stored
  (snapshots, their comparison, diagnostics), and your own sessions for the transcript reader, by session id among
  those the adapter lists. Only a harness and a project the server lists is ever read; anything else is refused (400).
- Writes follow the rules in "The UI as the primary interface" above; there is no `--allow-edit` flag (decided
  2026-10-04 — it was planned for editing endpoints). **As built** (2026-10-04, `ui/server.py`'s `do_POST`), a POST
  must pass, in this order, or is refused with a JSON `{"error": why}`:

  | Rule | Refused with |
  |---|---|
  | `Host` names this server (`127.0.0.1:<port>` or `localhost:<port>`) | 403 |
  | no `token` in the query, even empty: a write takes the token from `X-Agentlint-Token` only, so an address that was pasted, logged or kept in history can't make one | 403 |
  | the `X-Agentlint-Token` header holds this run's token (compared in constant time) | 403 |
  | an `Origin`, when the browser sends one, is this server (`http://127.0.0.1:<port>` or `http://localhost:<port>`); `null` is refused | 403 |
  | `Content-Type: application/json` (a charset may follow). A cross-origin page can send that only after a CORS preflight, and nothing answers OPTIONS — `BaseHTTPRequestHandler` says 501 with no `Access-Control-*` header — so the browser never sends the write | 415 |
  | a `Content-Length`, and no `Transfer-Encoding` | 411 |
  | at most `MAX_BODY` (64 KB); the body is never read past it | 413 |
  | one JSON object, UTF-8, no `NaN` or `Infinity` | 400 |
  | a path the control writes (`/api/settings`, `/api/schedule`, `/api/forget`, `/api/welcomed`, `/api/suppress`, `/api/unsuppress`) or the tests write (`/api/situations/generate`, `/api/situations/<16 hex digits>`, `/api/onboarding`, `/api/jobs`, `/api/jobs/<job id>/stop`, `…/resume`, `…/salvage`); a server built without tests answers those 404 | 404 |
  | every value checked by the control (`ui/control.py`), which refuses with `Refused(status, why)`: a value out of range or of the wrong shape, a field it doesn't take, a harness name outside the choices `GET /api/settings` offers, Forget without the typed word (400); Forget while a runner is alive (409); the system's scheduler failing to install or remove the daily job (500, "the scheduler refused: …"); a server built without a control (404) | 400, 409, 500, 404 |

  Writes run one at a time (`write_lock`). The token is never logged: `log_message` stays silent, and a bug's
  traceback, printed before its 500, reaches no further than the checks above. `tests/test_ui_server.py` sends one
  request per rule. A server built without a control (reports only) answers every write, and `GET /api/settings`,
  404.

## Non-goals

- Not a hosted service. Localhost only, always.
- Not multi-user, not shared, no accounts.
- Not an editor for *writing* new instructions — this tool removes and diagnoses; authoring belongs
  elsewhere.
- Not a live session monitor. It reads the last session; it doesn't attach to a running one.
